- [x] **A placeholder credential counts as no credential, 29 Aug** — an unset
  secret left at `YOUR_KEY_HERE` routed every call to an endpoint answering
  "API key not valid", and the failure was quiet: embeddings died one clause at
  a time and the app said "no regulation covers this" while holding the
  regulation. Falling back to Vertex makes a misconfiguration a cost line, not a
  wrong answer
- [x] **A citation points at a passage or at nothing, 29 Aug** — clause text is
  located inside the document and highlighted in place. Matching reports
  `exact`, `approximate` or `not_found`; an unlocatable clause is listed as
  unlocated rather than pointed at the nearest paragraph. Highlighting the
  wrong sentence would be worse than highlighting none
- [x] **Unrecognised ingredient names get an answer, not silence, 29 Aug** —
  `core/substances.py` never overrides the strict matcher; it explains its
  refusals and offers names for the user to pick. A food is called a food, and
  the sentence says out loud that nothing being checked is not a pass
- [x] **The app ships with rules, 28 Aug** — a new workspace no longer starts
  empty. `scripts/build_library.py` cuts 28 verbatim excerpts out of the two
  regulations already in `data/regulations/` and the user loads them with one
  button. They are *ingested*, not injected: same hash, same Pub/Sub message,
  same extraction, same guardrail as an upload, so nothing enters the graph
  through a path an upload could not use. Excerpts are cut, never rewritten
- [x] **A rule binds only the kind of product it was written for, 28 Aug** —
  forced by the library: with limits for every food category in the graph,
  matching on jurisdiction and substance alone failed a drink powder against a
  dairy-dessert limit. Powder and liquid stay one family (the BPOM tables say
  "dihitung terhadap produk siap konsumsi"); an unstated product type still
  binds, as the documented wildcard
- [x] **Upload metadata is read, not asked, 28 Aug** — jurisdiction, source type,
  title and effective date come from the document itself (`core/detection.py`,
  deterministic). The form asks only what could not be read, and the user can
  always override. Deliberately *not* an LLM call: upload must stay fast, and
  the source type caps what a clause is allowed to do, so it belongs in typed
  code with tests, per the standing rule that deterministic code owns every
  mutation. On a tie the lower authority wins
- [x] **Minimal onboarding is in scope, 26 Aug** — phase 7 listed "onboarding flows" as out of scope, written on the assumption that we always drive the demo. A judge opens the hosted URL cold with no product and no regulation PDF. So: bundled sample regulations, a one-click demo seed, and a three-step checklist that persists until done. No tour, no coach marks, no modal — those stay out
- [x] **Readiness as counts, not percentage?** — Counts (phase 4 will render issue counts). *User confirmation still welcome; nothing built contradicts it*
- [x] **Two GCP projects or one?** — **One** (`regulens-506014`), as already provisioned 19 Aug
- [x] **Repo public or private?** — **Public**, verified public on GitHub 19 Aug
- [x] **Composite confidence weights** (22 Aug) — `0.3·parse_quality + 0.4·self_consistency + 0.3·authority_tier`, from the concept doc's model. Self-consistency = best-match field agreement between the two Gemini samples over substance/limit/unit/product_type
- [x] **Decision events belong to reconciliation** (22 Aug) — phase 2 persists clauses as `pending_reconciliation` with no `clause_created` event; phase 3's verdict application writes exactly one of {created, superseded, conflict_opened, flagged_review} per clause. Keeps one-decision-one-event true and UC-D's zero-mutation assertion meaningful
- [x] **Upload cache key** (22 Aug) — identical bytes short-circuit when the prior document reached a terminal state (`extracted`/`reconciled`), not only `reconciled`; otherwise the cache could never hit before phase 3 exists
- [x] **Real corpus numbers override the sketch numbers** (23 Aug) — EU Annex II 14.1.4 is 150 mg/kg for E210-213; BPOM 14.1.4.x reads 400–900 mg/kg. Extraction follows the documents; the "0.05% vs 0.10%" pair stays a demo-narrative baseline seeded in phase 7, never presented as extracted fact
- [x] **Substance-family equivalence** (23 Aug) — EU limits the group "Benzoic acid — benzoates (E210-213)"; BPOM limits natrium benzoat computed "as benzoic acid". The guardrail compares across that documented shared basis (`_SUBSTANCE_FAMILIES` in `core/guardrail.py`); retrieval and requirement materialization use the same families. Not a guessed mapping — both documents state it
- [x] **Cross-jurisdiction conflict decided in code, not by the judge** (23 Aug) — different jurisdictions with different limits is deterministically a conflict; the judge is consulted ONLY for same-jurisdiction pairs whose effective dates do not settle the supersede question
- [x] **Unique image tags per deploy** (23 Aug) — Cloud Run skips revision creation on an unchanged tag, so builds pass `SHORT_SHA=<sha>-<HHMMSS>`; a plain git short-SHA silently redeploys nothing
- [x] **Gemini reached through the Developer API, not Vertex** (28 Aug) — the
  hackathon accepts "Gemini 3.5 or newer accessed through Gemini API **or**
  Vertex AI", and the Developer API's free tier covers `gemini-3.5-flash` and
  the embedding models outright. Vertex was 76% of the bill. `GEMINI_API_KEY`
  switches every call; unset, the Vertex path is unchanged, so this is one env
  var to roll back. The key must come from a project with **no billing linked**
  — linking billing promotes it to the paid tier. Cost of the switch: embedding
  vectors are model-specific, so the corpus needs `scripts/reembed.py` once
- [x] **Cloud Build runs on the default machine type** (28 Aug) — the 2,500
  free build-minutes apply to `e2-standard-2` only. The build was pinned to
  `E2_HIGHCPU_8`, which earns none of them; 23 builds cost Rp 41,070. Builds
  get slower and free
- [x] **A verification script that cannot fail is worse than no script,
  29 Aug** — `verify_e2e.sh` printed `ALL CHECKS PASSED` while a check crashed:
  every check was a pipeline ending in a Python assertion and nothing read the
  exit status. Each one now ends in `|| fail "<name>"`. The fix immediately
  exposed that the baseline check had been failing in silence on every re-run,
  because the script uploads the EU document and never removed it, so "Germany
  must read unknown" could only hold the first time it was ever run
- [x] **A document can be deleted, 29 Aug** — a product could always be deleted
  and the document you uploaded by mistake could not, so the wrong PDF stayed in
  the rulebook unless you had Firestore access. `DELETE /documents/{id}` takes
  the clauses, the requirements they produced, the conflicts they opened and the
  debug record, then re-evaluates every affected product: a delete that leaves a
  stale red verdict on screen is worse than no delete. Both verification scripts
  now clean up after themselves, which is what makes them repeatable
- [x] **Three agents run for real; the fourth is a smoke test and says so,
  29 Aug** — the repo had four ADK agents and used one. `build_query_agent` and
  `build_reconciliation_agent` were defined and never called, while the README
  table called Query "genuinely agentic". Query is now the real answer path —
  it picks its own retrieval tools, and every id its tools serve is recorded so
  the citation check has something real to validate against. Reconciliation is
  wired at the judge call and **only** there: a 55-clause annex would otherwise
  be 55 agent runs on the critical path, and the deterministic classification
  settles every other case in microseconds. Impact keeps no agent at all,
  deliberately — pass/fail against a numeric limit is arithmetic. `adk/agent.py`
  stays the phase-0 smoke test and is now labelled as one instead of counted as
  a stage. Every agent falls back to the deterministic path on failure
- [x] **An agent may not present an ungrounded answer as a grounded one,
  29 Aug** — found by the deployed E2E within minutes of wiring the query agent:
  asked about a country with no ingested regulation, it wrote "there is no
  information available" *and cited the clauses it had looked at*, so the answer
  came back `refusal: false` with citation cards under a sentence saying there
  was nothing. The agent now has one word for emptiness (`INSUFFICIENT_EVIDENCE`)
  and typed code turns that into the ordinary refusal. A single token is
  checkable; a sentence explaining itself is not
- [x] **One file, one command, 29 Aug** — `cloudbuild.yaml` hardcoded this
  deployment's own `*.run.app` hostnames, so a clone's web app called our API
  and our CORS list. `regulens.env` is now the only file anyone edits and
  `scripts/quickstart.sh` the only command anyone runs; both `*.run.app` URLs
  are computed from the project number, which Cloud Run makes knowable before
  the first deploy, so nothing is pasted by hand and the deploy stays one build
- [x] **Latency is a property of the document, not of the pipeline, 29 Aug** —
  re-measured with `scripts/measure_latency.py` rather than remembered. A single
  pasted rule is 25.5s upload→re-evaluated; the 4-page EU annex excerpt is
  174.3s, and 72% of that is extraction emitting 55 verbatim clauses. Output
  tokens are the floor. The two self-consistency samples were made concurrent
  (measured 95.9s and 110.4s inside a 110.4s window, so the sum is no longer
  paid), embeddings batched once per document instead of one call per clause,
  and the worker's blocking handlers moved off the event loop. Splitting a
  document into concurrent pieces was built and does not help this document:
  the excerpt is dense, not long, and stays one piece
- [x] **Infra stays in `asia-southeast1`** (28 Aug) — checked against the free
  tier per service. Cloud Run's free tier is region-independent and the Gemini
  API is a global endpoint. Only Cloud Storage's 5 GB is US-region-only, and
  that line was Rp 559; moving the bucket would add cross-region latency on
  every upload to save pennies. Retention rules, not relocation
